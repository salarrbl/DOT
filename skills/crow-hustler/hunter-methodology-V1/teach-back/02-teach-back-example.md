# Discovered SSRF in Shopify's Image Proxy — Chained to AWS Metadata Access

**Date:** 2026-07-06
**Session Type:** hunt
**Target:** Shopify (via HackerOne)
**Duration:** 3h 20m

---

##  What We Did Today

Tested Shopify's image CDN proxy (`cdn.shopify.com/s/files/...`) for SSRF. The proxy fetches images from external URLs to resize them. We found that it connects to internal AWS metadata (169.254.169.254) BUT blocks access to secrets. Discovered the proxy also resolves internal Shopify hostnames. This is a blind SSRF with internal DNS resolution — useful for port-scanning internal services.

---

##  What I (The Agent) Learned

- Shopify's image proxy uses an allowlist for URL schemes (http, https only — `file://`, `gopher://` are blocked)
- The proxy resolves DNS before fetching. This means you can control DNS resolution to point to internal IPs
- AWS IMDS v2 is enforced (token required). Proxy returns 403 for metadata paths — but the 403 ITSELF proves internal access exists
- Internal Shopify hostnames (`.shopify.io`, `.shopifycloud.com`) resolve through the proxy — this is a server-side DNS rebinding vector
- The proxy has a 10-second timeout — fast internal scans are possible, slow services will timeout
- Burp Collaborator confirmed DNS resolution, but HTTP response was never received from Collaborator (Shopify outbound filters block it)

##  New Technique: DNS-Based Internal Infrastructure Mapping

**Technique:** Use a blind SSRF to discover internal hostnames and map microservices.

**How YOU do it (without me):**
1. Find any endpoint that fetches external URLs (image proxy, webhook tester, PDF generator, link preview)
2. Instead of `http://127.0.0.1`, try `http://internal-service-name.company.com`
3. If the response is different from a random nonexistent hostname, you discovered something
4. Build a wordlist of common internal hostname patterns: `admin`, `api`, `internal`, `staging`, `dev`, `monitoring`, `kibana`, `grafana`, `jenkins`, `vault`, `consul`, `nomad`, etc.
5. Use the response differences (time, error message, status code) to differentiate "exists" vs "doesn't exist"

**Time:** 10 min per endpoint
**Tool:** Just Burp Intruder + your wordlist. No special tools needed.
